# 桌面优先架构方向

2026-11-16：以当前桌面端为主，保留 React、TypeScript、Python、SQLite、pywebview 和 Windows DPAPI。暂缓 NAS、FastAPI、Docker 与多端账户系统，不通过换框架承诺下载提速。

## 当前交付

0.7.6 从独立 `RemovalManager` 开始拆分应用职责，提供可恢复的删除日志、平台/内容复合过滤身份及当前库副本的回执代次。X 队列继续通过兼容索引运行，旧 JSON 与外部移动的去重保障保留。界面新增独立移除/过滤组件。

文件清理由后台线程执行，先过滤、定向停止相关任务并等待释放文件，再校验已登记的路径和文件归属，回收完整媒体、清理受管理的分片。数据库与完成回执通过代次防止旧状态复活。取消过滤本身不提交下载；重新发现发生在下一轮新扫描。

## 后续逐步实施

1. 建立来源、内容（作者可选）、媒体资源、文件位置和任务五类职责，X 数据通过兼容层迁移，采用版本化备份迁移。
2. 拆分下载、媒体库、来源、设置应用服务，明确桥接请求/响应与验证；React 拆分页面、卡片和数据获取职责。
3. 将解析、下载、扫描、缩略图按各自负载限制并发，保留持久任务状态、重试、中断恢复和增量通知；空闲时降低轮询频率。
4. 分别规划托盘运行、关闭窗口行为、开机启动、定时订阅、休眠唤醒和外接盘断开恢复。不断电不能替代程序保持运行与电脑保持唤醒。
5. X 采集适配通用核心后，按本地导入、Telegram、B 站逐项验证；不把未来展示适配当作已经支持真实下载。

核心业务应独立于窗口，未来确有手机/其他电脑访问需求时，再增加服务接口。日常在 develop 验证与提交推送，仅明确发布时合并 main 和打包。
