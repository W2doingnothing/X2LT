# 通用媒体模型（0.7.8）

本次是兼容式的数据层迁移。实际下载继续使用现有 X 下载器，没有增加其他平台下载、本地导入或云盘入口。

## 关系与身份

来源使用平台和作用域共同标识；作用域可表示频道、账号或本地集合。内容编号只在其来源内唯一，媒体编号只在所属内容内唯一。不同平台或频道的相同编号不会合并。

一条内容可以没有作者，并关联多个图片或视频。每个媒体可以有多个画质、扩展名和分辨率版本，每个版本可以有多个保存位置。任务单独关联版本与可选位置；内部模型允许导入、校验和处理任务，不要求创建虚假的 X 下载任务。上述通用写入接口目前仅供内部使用。

首次保存顺序记录在媒体层，多画质和多库副本不重复计数。历史没有可靠添加日期的记录保持未知。

## 迁移与兼容

初始化时先保留原有 jobs、标签、过滤、移除及转移表，再添加 model_* 表。非空队列使用 SQLite 备份接口生成同目录的 `.pre-model-v1.bak`，包括尚未检查点的 WAL 内容；备份成功后才开始迁移，不覆盖已有备份。备份包含私人记录，不应提交或分享。

任务按 ID 分批迁移，每批数据与游标共同提交。中断后从已提交游标继续；迁移完成后不重复回填。旧任务仍是 X 下载的执行依据，其新增和更新通过数据库触发器在原事务内同步到新关系，涵盖状态、文件位置、校验结果和移除代次。

资源列表与统计已读取通用模型。X 的资源标识、标签和对外位置编号保持兼容；非空来源作用域进入资源身份，防止串库或串频道。旧 JSON、下载目录和媒体文件均不因迁移移动或重写。

## 当前边界

作者聚类、库内内容查询、标签、预览、系统打开及媒体移除仍保留现有 X 兼容链路。通用记录的内部接口不代表这些完整产品流程已支持新来源。后续接入平台时需要补齐来源适配、权限与路径批准、标签身份和通用文件操作，不能直接把内部记录当作可运行的新平台任务。

原下载请求策略、断点续传和完整性检查本次保持原流程。队列调度、增量事件与更多前端组件拆分可在后续小版本逐步推进。
