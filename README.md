# X2LT

**X to Local or Telegram**，一个 Windows 桌面媒体归档工具。

当前版本支持将 X / Twitter 的点赞中的图片、视频和单条推文媒体保存到本地。Telegram 上传尚未实现。

[下载 Windows 版](https://github.com/W2doingnothing/X2LT/releases/latest) · [更新记录](CHANGELOG.md) · [反馈问题](https://github.com/W2doingnothing/X2LT/issues)

## 功能

- 下载最近点赞、全部点赞，或粘贴推文链接；可选仅视频、仅图片、视频＋图片。
- 最高画质、720p、480p；最多同时两个媒体文件，每文件最多四路分段。
- 暂停续传、失败重试、长度与 SHA256 校验。
- 一键脱壳集中媒体，可回退至原目录，也可按哈希查找手动移动的视频。
- JSON 完成记录留在原目录，视频被移走后仍跳过重复下载。
- Cookie 和含密码的代理配置用 Windows DPAPI 加密保存。
- React 桌面界面，支持深浅主题、HEX / 色盘主题色与多媒体库配额管理。

支持平台原生视频和 JPEG/PNG/WebP 图片，不包含 GIF 或外链媒体。读取点赞需要登录。

本文对应 develop 中的 0.7.4 开发版；正式发布包以 Release 的版本说明为准。

## 下载与启动

1. 从 [Releases](https://github.com/W2doingnothing/X2LT/releases/latest) 下载 `X2LT-版本号-windows-x64.zip`。
2. 完整解压到可写目录，双击 **本地视频下载器.exe**，也可运行 **start-local-video.cmd**。
3. 保留旁边的 **local-video-runtime** 文件夹，它是程序所需的运行库。

发布环境为 Windows 10/11 x64，下载包未进行代码签名。可用同一 Release 的 `SHA256SUMS.txt` 检查文件完整性。

桌面版需要 [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)，使用系统安装的 Evergreen Runtime；不需要安装 Node.js 即可运行 Windows 下载包。

## 界面

0.6.0 默认使用 React + TypeScript + Vite，Tailwind 与 shadcn/Radix 组件，pywebview + WebView2 提供 Windows 窗口。左侧切换总览、下载任务、本地媒体、媒体整理和设置；左下角切换明暗模式，设置“外观”支持 HEX、色盘、预设主题色及实时预览。浏览器原型始终标注模拟数据，不访问真实账号；桌面版连接本地 Python 服务。

0.7.0 使用 OKLCH 从源重点色派生整套深浅配色，包含背景、表面、文字、边框与按钮各状态；输入 HEX 是源色，实际按钮色会按模式和可读性调整。同步状态条显示读取、已发现、已处理、成功/失败/跳过；总量未知时显示动效，不虚报百分比。读取与下载可并行。

总览下方是媒体库入口，支持本地 JPEG/PNG/WebP 图片（最多 16 MiB）或 emoji 封面。导入的封面保存到应用目录，原图移动不影响显示。点击库进入本库消息页，默认显示至少一个媒体已完成的归档，可切换全部、未完成、已忽略；部分完成有独立状态，其他库的媒体不混入。本页仅展示软件已管理的记录，不自动导入目录里的任意媒体。

卡片左侧可添加 `#标签`（窄屏移至标题区域），输入后按 Enter 或逗号提交；支持中英文、数字、下划线和连字符，每个标签 1–32 字，每条消息最多 20 个。标签按消息共享于各媒体、画质和库，文件整理或移动不丢失；移除可撤销。点击标签筛选，或搜索 `风景 #旅行 #参考`；多个标签需全部满足，并与正文/账号关键词组合。可筛选未打标签、管理重命名/合并或删除标签关联，不删除媒体。

推主头像仅在已有提取元数据提供时加载，旧任务可使用“补全预览”。离线或缺失头像显示占位；头像与媒体预览共享并发和缓存限额。首次升级会先备份旧非空数据库到 `queue.sqlite3.pre-catalog-v1.bak`，再分批整理消息索引；迁移失败可重试，下载记录及 JSON 去重依据保持原样。备份含私人记录，请与应用数据一起妥善保管。

0.5.1 起同一条推文的媒体合在一张卡内。标题取正文首行，下方的 `@推主号` 可点击打开主页；最多显示三个媒体，左右箭头、Shift+滚轮或横向拖动查看其余媒体。未完成媒体有灰色遮罩和独立环形进度，等待、失败、暂停及未知长度分别显示状态。点击媒体或“详情”可看完整正文、较大预览，并切换媒体、画质或保存副本。媒体库内按推文展示，具体媒体及画质/媒体库副本在详情中切换。视频使用静态封面，“打开已下载文件”调用系统播放器；图片可查看较大预览或在系统看图工具打开原图。

旧任务缺少正文/封面时，详情中点击“补全预览”，只更新已有任务元数据，不新增下载。缩略图按可见页面后台加载、使用同一代理，失败不影响下载；设置“账号与下载”中可清空预览缓存（上限 500 MiB）。缓存位于应用私有目录，不随脱壳移动。

## 导航与隐私模式

0.7.1 总览采用外层媒体库容器与内部紧凑卡片，右上角加号添加库。进入库后保持总览选中；面包屑或再次点击总览返回库列表。切换栏目时，会话内分别保留各栏目和各库的搜索、筛选、分页、选择、媒体翻页及滚动位置；重开软件重新开始浏览。

0.7.2 库内只展示已保存媒体，下载管理保留在“推特下载”。可切换为“博主”视图，按当前库内已保存媒体数量排列，点击进入博主合集；支持名称/账号搜索、标签筛选，并保留各层返回位置。忽略只阻止后续下载，不隐藏已保存收藏。推文卡片显示推主名、账号与可展开正文，媒体角标采用半透明黑底，页面右侧提供页首尾导航。

0.7.4 总览展示媒体库、视频、图片和本地占用。点击数量或“查看全部”可浏览相应资源，支持内容/文件名搜索、标签筛选与分页；最近添加最多展示 8 个唯一资源。多个库副本和画质版本只统计一次，可在资源详情中选择位置与版本，并通过系统播放器打开。新资源按首次保存排序，重新下载或转移不置顶；历史添加时间显示未知。热度图暂缓。

博主卡片左上角星标可置顶，右键或右上角更多菜单可归档，并支持撤销。归档博主从主列表隐藏，在“打开归档”中查看及取消归档；旧“其他博主”设置自动沿用为归档。归档保留星标、文件和下载记录，不影响资源统计或下载。

“媒体库”栏目与总览使用相同的库卡片，进入库时保持所属栏目选中，各自保留浏览状态。“媒体工具”提供“媒体转移”（原媒体脱壳），支持集中转移及转移回退。Backspace 返回逻辑上一层，先关闭最上层弹窗/菜单；输入文字、输入法及组合键不触发返回。下载信息和操作仅在推特下载页显示。

下载任务可折叠，内含“推特下载”和“电报下载”。电报下载目前仅占位，不提供下载、登录或账号操作。

设置“隐私”可开启并保存隐私模式：媒体缩略图和图片封面默认模糊，推文标题和正文默认折叠。首次点击显示当前内容，媒体再次点击进入详情或打开文件；作者账号、标签、状态和进度保留。切换栏目/库、关闭再开启隐私模式或重启后重新遮蔽，临时展开状态不长期保存。

## 媒体库与存储上限

每个媒体库必须有一个 emoji 标识，可从预设中选择或输入组合 emoji；标识与图片封面独立保存，重置图片会保留标识。总览和媒体库卡片下方显示容量条：有配额显示本库配额，无配额显示磁盘空间，另列本库占用及可用容量。

设置“媒体库”通过系统文件夹选择器添加库，支持多个独立目录、命名、设置默认库及每库最大存储量；0 或留空表示不限额。重复、嵌套、符号链接/目录联接路径不能作为新库。旧保存目录自动成为初始库，不重写已有任务或解密凭证。

每张库卡显示路径、实际已使用容量（含库内其他普通文件和下载暂存）、配额剩余、所在磁盘剩余/总容量和当前可用容量。配额独立，磁盘空间由同盘的库共享；翻页和标签筛选读取最近的容量缓存，可手动刷新；下载操作结束后更新容量。下载层预留空间前仍执行真实扫描。磁盘总容量不是该库的独占容量。

新建任务及继续下载时选择目标库。修改默认库只影响后续选择，运行中的任务捕获原目录不变。空间不足时任务暂停并保留原因、分段和历史，可提高配额、清理空间后手动继续；不会自动清理媒体。

配额检查计入峰值暂存：已知大小按两份文件加 16 MiB 余量预留；未知长度按设置中的单文件上限预留两份。因此最终文件能放下但分段合并空间不足时也会暂停。其他程序对磁盘的写入不受本工具控制。

整个库被手动移动后，编辑库并重新选择其真实位置，程序更新队列及可识别完成回执的路径，不移动文件；记录冲突时拒绝自动合并。移除库仅移除管理关系，文件和下载历史保留，重新添加原位置可继续使用。失效路径显示离线状态。

## 账号与代理

填写 X 用户名、`auth_token`、`ct0`，点击“保存加密凭证”。这两个 Cookie 可在自己已登录 X 的浏览器开发者工具中查看，属于 `x.com`。它们相当于登录凭证，请勿分享或提交到 Issue。

代理示例：`http://127.0.0.1:7890`、`socks5://127.0.0.1:7890`。端口请使用代理软件实际监听值。SOCKS5 使用远端 DNS；设置中密码框留空保留已保存值，点击“禁用代理”切换直连，不自动继承系统代理。

设置和队列位于 `%LOCALAPPDATA%\X2TLocalVideo`，该目录名为兼容已有记录保留。凭证用当前 Windows 用户的 DPAPI 加密；更换电脑或账号后通常需要重新填写。DPAPI 不防御同一用户权限下运行的恶意程序。

## 推文多选与忽略

下载页可勾选推文、全选当前页，选择会跨页保留，顶部显示总选择数。“忽略所选”作用于全部选中推文；单张卡也可直接忽略。切换“未完成 / 已忽略”筛选会清空选择。

忽略名单按推文 ID 生效，跨重启、画质和保存目录保持；该推文中未开始及以后同步发现的媒体不再下载。**已开始的媒体允许完成，已有文件、分段和完成记录保留**，其他推文继续处理。归档列表也可忽略所选媒体所属的推文。

在“已忽略”筛选中可单独或批量取消忽略。取消只恢复下载资格，**不会在当前运行轮次自动开始**，需要再次手动继续或同步。忽略中的推文也不能强制重下，应先取消忽略。名单保存在应用私有队列内，不依赖媒体文件位置。

## 下载、暂停与校验

选择目标媒体库、画质、连接数和大小上限，再点击下载。新建任务默认“视频＋图片”，可选择仅视频或仅图片并记住选择。这个选择控制新解析出的媒体，继续未完成仍会处理队列中已有的任务。

- “最新点赞”读取最近 50 条含媒体的推文窗口，不保证得到 50 个媒体文件。
- 文件默认保存为 `保存目录/画质/作者/推文ID/推文ID_媒体序号.mp4`，各画质分开保存。
- 图片保存在 `保存目录/images/作者/推文ID/推文ID_媒体序号.jpg（或 png/webp）`，一张图一个任务；图片去重不受视频画质选择影响。
- 暂停会保留 `.parts` 分段；下次点“继续未完成 / 重试”。关闭窗口也会先暂停，当前请求可能需约 20 秒结束。
- 仅在 Range、已知长度和可靠资源校验器都可用时启用安全分段与跨次续传；否则自动单流，暂停后可能需要重下。
- “校验已完成文件”只检查本地文件，不自动补下载，缺失或损坏仍保留历史。
- 补回视频时选中条目，点“强制重新下载选中项”；强制任务暂停后仍可继续。

SHA256 是本地一致性记录，不是平台内容签名，也不保证完整解码。缺少服务器总长度会明确提示。若系统 PATH 中有 ffprobe，会额外检查视频流；发布包不附带 ffprobe。

下载分段、合并与正式文件可能同时存在，需要额外磁盘空间。

## 脱壳、回退与防重复

“一键脱壳 · 集中视频”把当前保存范围内的已完成媒体移到 `保存目录/集中视频`；也可用“选择脱壳目录…”指定位置。

- 移动 MP4/JPG/PNG/WebP，`.verified.json` 留在原分层目录，记录视频标识、画质、大小、SHA256 和最近位置。
- 有完成记录时，即使视频被手动移动或删除，再次同步仍跳过下载。JSON 表示曾下载完成，不证明文件目前存在。
- 保留原目录中的 JSON 和应用队列。**顶部“保存目录”保持原值**，改变它会创建另一个归档范围，可能重复下载。
- 新媒体仍按各自层级保存，之后可再次脱壳。

“脱壳回退”恢复原目录。视频被手动移动或改名后，用“查找并回退…”选择它所在的文件夹，程序只在该文件夹及子目录按大小和 SHA256 查找，不扫描全盘。

迁移先复制校验、保存位置记录，再清理旧副本。异内容同名文件不覆盖；暂停或失败优先保留数据，再次操作可收尾。旧版本随视频移动的 JSON 会安全归回原目录，无法确认归属的文件保留并提示。

## 速度调整

设置中的“请求策略”提供保守 1 MiB（默认）、均衡 4 MiB、吞吐 8 MiB。高延迟且连接稳定时可尝试均衡；断流较多时保守通常更合适。单次请求变大不会增加连接数，也不保证实际提速。

默认四个连接。若重置较多或更慢，可试一个或两个；切换连接数可能使旧分段无法复用。720p / 480p 从实际提供的版本选择，竖屏按短边限制。

提取与下载均使用填写的代理，视频直接来自平台 CDN。实际速度取决于节点到 CDN 的吞吐，多连接不保证固定倍数提速。

## 源码运行与构建

需要 Windows、Python 3.11+、Node.js 24+ 和 WebView2；当前构建使用 Python 3.14.3 x64。Tkinter 仅用于旧界面兼容与测试。

```powershell
python -m venv .local-runtime
.\.local-runtime\Scripts\python.exe -m pip install -r requirements-local-video.txt
npm ci --prefix frontend
npm run build --prefix frontend
.\.local-runtime\Scripts\python.exe launch_local_video.py
```

也可运行 `setup-local-video.cmd` 后用 `start-local-video.cmd` 启动。

```powershell
.\.local-runtime\Scripts\python.exe -m unittest discover -s tests -v
npm test --prefix frontend
.\.local-runtime\Scripts\python.exe -m pip install -r requirements-build.txt
.\build-local-video.ps1
```

完整构建依赖版本在 `requirements-local-video-lock.txt`。发布流程见 [CONTRIBUTING.md](CONTRIBUTING.md)，依赖及对应源码见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

`npm run dev --prefix frontend` 启动独立模拟数据原型；真实账号接口只在桌面窗口启用。`--legacy-ui` 可启动旧 Tk 界面用于兼容性回退，已有媒体库配额会约束下载；建议日常使用默认界面。0.5.1 本地包可保留作版本回退，不要同时打开两个使用相同队列的实例。
